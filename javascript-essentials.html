Every JavaScript program you will ever write — from a simple calculator to the entire Facebook interface — is built on variables. They are the containers that hold your data.

What is a variable?

Think of a variable as a labelled box. You put a value inside, and later you can look inside by using the label.

let name = "Chisomo";
let age = 22;
let isStudent = true;

The three keywords

  • let — a variable that can change (use this most of the time)
  • const — a variable that cannot be reassigned (use this for values that stay fixed)
  • var — the old way. Avoid it. It has confusing scoping rules.
let score = 10;
score = 20;          // OK

const pi = 3.14;
pi = 3.15;           // ERROR — can't reassign const

Data types

JavaScript has several built-in types. The ones you'll use daily:

  • String — text, wrapped in quotes: "hello", 'world', `template`
  • Number — 42, 3.14, -7 (no separate integer type)
  • Boolean — true or false
  • null — intentionally "no value"
  • undefined — a variable declared but not assigned yet

Seeing your values — console.log

The console is your best friend. Use console.log() to print anything:

console.log("Hello, Malawi!");
console.log("Age:", age);
console.log(2 + 3);      // 5
Open your browser's developer tools (F12) → Console tab to see output. In this course, we capture the console for you below the editor.

Programs need to make decisions and repeat tasks. That's what control flow means: telling your code when to do something, and how many times.

if / else if / else

let score = 75;

if (score >= 80) {
  console.log("Grade: A");
} else if (score >= 70) {
  console.log("Grade: B");
} else if (score >= 60) {
  console.log("Grade: C");
} else {
  console.log("Grade: F");
}

JavaScript checks each condition top to bottom, and runs the first block that is true.

Comparison operators

  • === — strictly equal (same value AND same type) — always use this
  • !== — strictly not equal
  • >, <, >=, <= — greater / less than
Avoid == and != (double equals). They do type coercion, which causes bugs: "5" == 5 is true, but "5" === 5 is false.

Logical operators

  • && — AND (both must be true)
  • || — OR (at least one must be true)
  • ! — NOT (flips true/false)
let age = 20;
let hasID = true;

if (age >= 18 && hasID) {
  console.log("You may enter.");
}

Loops

A for loop is the most common. It runs a block a specific number of times:

for (let i = 1; i <= 5; i++) {
  console.log("Count:", i);
}

The three parts: start (let i = 1), condition (i <= 5), step (i++).

A while loop runs as long as a condition is true:

let n = 0;
while (n < 3) {
  console.log(n);
  n++;
}

Functions are reusable blocks of code. They let you write logic once and run it as many times as you need.

Declaring a function

function greet(name) {
  return "Hello, " + name + "!";
}

console.log(greet("Malawi"));   // "Hello, Malawi!"
console.log(greet("Chisomo"));  // "Hello, Chisomo!"

Parts of a function:

  • function — the keyword
  • greet — the function name
  • (name) — the parameter list (input)
  • return — the output. Stops the function and sends a value back

Arrow functions (modern style)

const add = (a, b) => a + b;
console.log(add(3, 5));   // 8

const square = n => n * n;
console.log(square(4));   // 16

If the body is a single expression, you can skip the braces and the return keyword — the expression is returned automatically.

Scope

Variables declared inside a function are local — they disappear when the function finishes.

function test() {
  let secret = "hidden";
  console.log(secret);   // works
}

test();
console.log(secret);     // ERROR — secret is not defined here
Always give your functions clear names that describe what they do: calculateTotal, formatDate, isValidEmail — not doStuff or fn1.

The DOM (Document Object Model) is the browser's live representation of your HTML. JavaScript can read it, change it, add to it, and remove from it — all while the page is running.

Selecting elements

The main tool is document.querySelector(), which uses CSS selectors:

let title = document.querySelector("#title");       // by id
let para = document.querySelector(".msg");          // by class
let buttons = document.querySelectorAll("button");  // ALL matching
querySelector returns the first match. querySelectorAll returns all matches as a list you can loop over.

Changing text

title.textContent = "New title";     // safe, plain text
title.innerHTML = "<em>New</em>";     // parses HTML (use carefully)

Changing styles and classes

title.style.color = "#00c853";
title.style.fontSize = "28px";

para.classList.add("highlight");
para.classList.remove("old-class");
para.classList.toggle("active");

Using classList is preferred over setting styles directly, because your CSS stays in one place.

Creating and adding elements

let newPara = document.createElement("p");
newPara.textContent = "I was added by JavaScript!";
document.body.appendChild(newPara);

Websites are boring without interaction. Events are how your code reacts to clicks, typing, scrolling, and more.

The pattern: select → listen

let btn = document.querySelector("#myBtn");

btn.addEventListener("click", function() {
  console.log("Button clicked!");
});

Two steps: (1) find the element, (2) attach a listener for an event type.

Common event types

  • click — user clicks the element
  • input — user types in a text field (fires on every keystroke)
  • submit — a form is submitted
  • keydown — user presses a key
  • mouseover / mouseout — mouse enters or leaves

Reading input

let input = document.querySelector("#nameInput");
input.addEventListener("input", function() {
  console.log("Current value:", input.value);
});

For form inputs, .value gives you the current text.

The event object

Every listener receives an event object with useful details:

document.querySelector("a").addEventListener("click", function(event) {
  event.preventDefault();   // stop the default behaviour
  console.log("Link clicked");
});

event.preventDefault() is essential for forms — it stops the browser from reloading the page when a form is submitted.

A common mistake: writing myBtn.addEventListener("click", myFunc()) — with parentheses. That calls the function immediately. Without parentheses, you pass the function as a value, which is what you want.

Almost every real app deals with lists of things — todos, messages, products, users. JavaScript gives you arrays and objects to handle them.

Arrays

let todos = ["Learn HTML", "Learn CSS"];
todos.push("Learn JavaScript");   // add to end
todos.pop();                      // remove from end
console.log(todos.length);        // 2
console.log(todos[0]);            // "Learn HTML"

Looping over arrays

todos.forEach(function(todo, index) {
  console.log((index + 1) + ". " + todo);
});

forEach runs a function once for every item. It receives the item and its index.

map and filter

map transforms every item into a new array:

let lengths = todos.map(function(todo) {
  return todo.length;
});
// [10, 9, 16]

filter keeps only the items that pass a test:

let short = todos.filter(function(todo) {
  return todo.length < 10;
});
// ["Learn CSS"]

Objects

An object groups related values under named keys:

let user = {
  name: "Chisomo",
  age: 22,
  isStudent: true
};

console.log(user.name);       // "Chisomo"
user.age = 23;                // update a field
user.email = "c@example.com"; // add a new field

Arrays of objects

The most common data shape in real apps:

let tasks = [
  { text: "Buy groceries", done: false },
  { text: "Study JavaScript", done: true }
];

tasks.forEach(function(task) {
  console.log(task.text, "-", task.done ? "✓" : "○");
});

Time to build something real. Over the next three lessons, you'll build a fully functional to-do app with add, delete, toggle, and localStorage persistence. This is the kind of project you can put on your portfolio.

What is a to-do app?

A to-do app lets users:

  • Type a task and add it to a list
  • See all their tasks
  • Delete tasks they no longer need
  • Mark tasks as done
  • Come back later and find their tasks still there

The plan

We'll build it in three stages:

  1. This lesson: structure — HTML, form, empty list, selecting elements
  2. Next lesson: interactivity — add, render, delete
  3. Final lesson: persistence — save and load from localStorage

Step 1: Find your elements

Before you can change anything in the DOM, you have to grab a reference to it. The starter code below selects the form, the input, and the list, and logs each one to the console so you can verify they exist.

Rule of thumb: if you get null from a querySelector, your selector is wrong. Check for typos in IDs and classes — and remember that #id targets an ID, while .class targets a class.

Step 2: Understand the shape of the data

We'll keep an array called todos. Each item will eventually be an object with text and done:

let todos = [
  { text: "Learn HTML", done: true },
  { text: "Learn CSS", done: false }
];

For now, it's empty. Later lessons will populate it.

Your UI is set up. Now let's make it do something.

Step 1: A render function

The most important pattern in app development: the state drives the UI. Whenever todos changes, we call render() and the screen updates to match.

function render() {
  list.innerHTML = "";     // clear the list
  todos.forEach(function(todo, index) {
    let li = document.createElement("li");
    li.textContent = todo;
    list.appendChild(li);
  });
}

Notice we rebuild the list from scratch every time. This is simple and fast enough for our small app.

Step 2: Handle the form submit

form.addEventListener("submit", function(event) {
  event.preventDefault();          // stop the page from reloading
  let text = input.value.trim();
  if (text === "") return;         // ignore empty input
  todos.push(text);
  input.value = "";                // clear the input
  render();
});

The event.preventDefault() is critical. Without it, the browser will try to submit the form to a server and reload the page.

Step 3: Delete buttons

For each todo, create a delete button. When clicked, remove that item from the array and re-render:

let delBtn = document.createElement("button");
delBtn.textContent = "Delete";
delBtn.addEventListener("click", function() {
  todos.splice(index, 1);   // remove 1 item at position `index`
  render();
});

splice(index, 1) removes exactly one item from the array at that position. All items after it shift down.

Be careful with closures inside loops. Because index is declared with forEach's callback, each iteration gets its own copy — so the delete button always knows which item it belongs to.

Right now your app forgets everything when the page reloads. Let's fix that with localStorage.

What is localStorage?

localStorage is a simple key-value store built into every browser. It survives page reloads and browser restarts.

localStorage.setItem("key", "value");
let v = localStorage.getItem("key");    // "value"
localStorage.removeItem("key");

The catch: it only stores strings

You can't save an array or object directly. You have to convert it to a string first, and convert it back when loading. JavaScript gives us two tools for this:

  • JSON.stringify(value) — turns any value into a JSON string
  • JSON.parse(string) — turns a JSON string back into a value
let todos = [{ text: "Learn JS", done: false }];

// Save
localStorage.setItem("todos", JSON.stringify(todos));

// Load
let raw = localStorage.getItem("todos");
let loaded = raw ? JSON.parse(raw) : [];
console.log(loaded);   // [{ text: "Learn JS", done: false }]

Wrap in functions

It's cleaner to hide the JSON work in helper functions:

function loadTodos() {
  try {
    let raw = localStorage.getItem("todos");
    return raw ? JSON.parse(raw) : [];
  } catch (e) {
    return [];
  }
}

function saveTodos() {
  localStorage.setItem("todos", JSON.stringify(todos));
}

Now you call saveTodos() any time the array changes, and loadTodos() once at startup.

Always wrap JSON.parse in a try-catch. If the stored string is corrupted, parsing throws and crashes your app.

You did it

Your app now persists. Close the tab, come back, and your tasks are still there. This is the exact pattern used by real apps — just at a larger scale.
